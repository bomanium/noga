# media-qc

File-based quality control (QC) of video deliveries: a cheap, local, scriptable first pass for small post houses,
freelancers and archives, before files go to a broadcaster or platform. One report (HTML, JSON and an exit code for
pipelines) of a file's black spans, colour bars, line-up tone, silences, loudness (EBU R128), pixels outside broadcast
range, crop/letterbox, frame types, bitrate and keyframes, and its shot list, each figure saying how it is checked
against FFmpeg. Not a Netflix/DPP compliance replacement. A planned commercial product; `media-qc` and the `mediaqc`
command are working names until it gets a real one. Repo: `github.com/bomanium/media-qc` (private). Where the idea
came from, the market and the gaps: docs/notes/origin.md.

It builds on the owner's public libraries: ManagedCodecs (pure C# H.264/MJPEG/AAC decoding), ShotDetector and
FrameReader (FrameReader reads anything through FFmpeg in-process), and the picture and sound measures in
shotdetector-web's core (`src/ShotDetectorWeb.Core`: PictureMeter, PictureMeasures, Loudness, Mp4Audio; checked
against FFmpeg's signalstats, blackdetect, cropdetect and ebur128).

## Hard rules

- **Never commit customer media**, nor any media at all. Test files are generated by `tools/make-samples.sh` (ffmpeg
  lavfi sources: smptehdbars, testsrc2, color, aevalsrc tone, anullsrc, anoisesrc) into `samples/`, or are open films
  (e.g. Blender's) downloaded and pinned by SHA-256; both stay out of git (.gitignore ignores `samples/` and media
  extensions). A file someone sends to debug with stays on their machine.
- **Licences allow closed-source commercial use.** MIT, BSD, Apache-2.0 and the like. LGPL (ShotDetector.FastYuv,
  FrameReader.Native's FFmpeg build) only as separate, replaceable, dynamically loaded binaries, with its licence
  shipped beside them. No GPL or AGPL, also not through an FFmpeg build with `--enable-gpl` (libx264 and the like).
  Every dependency and its licence goes in docs/dependencies.md, in the PR that adds it.
- **Private repository**: nothing is published to NuGet (`IsPackable` is false in Directory.Build.props). CI runs on
  ubuntu only (private Actions minutes; Windows costs 2x, macOS 10x); external actions are pinned by commit SHA with
  the tag in a comment (`uses: actions/checkout@<sha> # v7`; `git ls-remote https://github.com/<owner>/<repo>
  refs/tags/<tag>`), and each workflow's token defaults to `contents: read`.
- **Decisions are the owner's.** Ask with the multiple-choice prompt (AskUserQuestion), the recommendation first,
  and record question, choices and answer in `docs/decisions/YYYY-MM-DD-<what>.md` (docs/decisions/README.md).
- **Every figure says how it is checked against FFmpeg** (which filter, which options, what tolerance), in the report
  and in a test.

## Working on this repository

- **PR pipeline**: work on a branch, push, open a PR, and merge it yourself (a merge commit) once CI is green on its
  head: it's version controlled, so anything can be redone (docs/decisions/2026-10-31-sessions-merge.md). A PR with
  a decision still open for the owner waits for the answer first. A private repository on GitHub Free has no
  auto-merge and no branch protection, so `main` isn't protected by settings: don't push to it directly all the same.
- **Backlog**: `docs/backlog.md`: Next (priority order), Waiting (on the owner or an outside event), Maybe. Items are
  list entries (What, then Why: and Status:) with a blank line between them. Take the first Next item; when one is
  Done (or Dropped, Won't do), move it to `docs/backlog-done.md` (created with the first one).
- **Asking the user**: whenever you need input (a choice, an approval, whether to take the next step), ask with the
  multiple-choice prompt, not with a question at the end of a reply.
- **Where work runs**: long work runs as cloud sessions; the owner's computer must stay free. A local clone, when
  there is one, is at `C:\dev\media-qc`.
- Before pushing: `dotnet test MediaQc.slnx` and `dotnet tool run bro format MediaQc.slnx --verify-no-changes`
  (CI runs both, and builds with `-warnaserror`).
- Code style: StyleBro (analyzers on build, rules in `.editorconfig`: shotdetector's conventions). The pre-commit hook
  formats the staged .cs files (`git config core.hooksPath .githooks` once per clone). By hand: `dotnet tool run bro
  format MediaQc.slnx`. The analyzers' version (Directory.Packages.props) and the tool's (.config/dotnet-tools.json)
  move together, by hand (Dependabot doesn't propose StyleBro prereleases).
- Line endings: LF everywhere (`.editorconfig`), unlike shotdetector's mixed files.
- Commit messages: what and why. Small commits.

## Layout

- `MediaQc.slnx`; `Directory.Build.props` (net10.0, nullable, version, StyleBro on every project, not packable);
  `Directory.Packages.props` (central package versions); `global.json` (SDK 10.0.1xx or later).
- `src/MediaQc.Core`: the checks. `Measurements` (what was measured, from either decoder: loudness, black, silences,
  bars, tone, pixels outside broadcast range, the active picture; seconds from the first frame), `Profile` (thresholds and measurement settings; `Profile.EbuR128` is
  v1's, `Evaluate` gives a `QcReport`), `QcReport`/`Finding` (severity, message, value, positions, what it is checked
  against; `ExitCode`), `Timecode` (SMPTE from the file's start timecode, drop-frame at 29.97/59.94), `ReportJson`
  (the JSON report, source-generated), `ReportHtml` (the HTML report, one self-contained page), `Product` (name and
  version). `Measurements.NotMeasured` lists the checks a decoder path doesn't measure yet, which the report says.
  `TimecodeTag.Pick`: the start timecode in ffprobe's JSON. `LineUp.End`: where the line-up tone ends; loudness is measured from there (`Measurements.LoudnessFrom`).
- `src/MediaQc.Ffmpeg`: the FFmpeg decoding path. `FfmpegMeasurer.Measure(file, profile)` fills `Measurements`
  through FrameReader (FFmpeg's libraries in-process, FrameReader.Native's): duration, frame rate, loudness (ebur128),
  silences (silencedetect), line-up tone. `Pictures`: the picture's measures from FrameReader's PictureMeter (black,
  bars, BRNG, cropdetect) for both paths, and FFmpeg's frames into it. `StartTimecode.Add`: the timecode tag through FrameReader's
  `MediaProbe.ProbeJson` (ffprobe's JSON in-process), for both paths.
- `src/MediaQc.Managed`: the managed decoding path, for H.264/AAC in MP4. `ManagedMeasurer` (`CanMeasure`,
  `Measure`) demuxes and decodes the H.264 and AAC with ManagedCodecs and measures with FrameReader's managed meters
  (LoudnessMeter, ReferenceToneFinder, SilenceFinder, PictureMeter): the same figures as the FFmpeg path, which a
  test checks on make-samples.sh's MP4.
- `src/MediaQc.Cli`: the `mediaqc` command (`CommandLine.Run`): `mediaqc check FILE [--out FOLDER] [--warnings-fail]`
  measures FILE (the managed path for H.264/AAC MP4, the FFmpeg path for the rest), judges it by `Profile.EbuR128`, writes FILE.qc.html and
  FILE.qc.json, prints the findings and exits 0 passed, 1 failed, 2 usage or read error, 3 warnings.
- `tests/MediaQc.Tests`: xunit. The FFmpeg path's tests generate their file with FrameReader's TestMedia and compare
  with the `ffmpeg` command line (`FfmpegCli`), which must be on PATH (CI installs it). `SampleTests` do the same on
  make-samples.sh's programme in each format; their fixture runs make-samples.sh into `samples/` when the files
  aren't there or an older script made them (`samples/.make-samples.sha256`) (bash, ffmpeg with libx264; ~1 min the first time).
- `tools/make-samples.sh [folder]`: generates the test files (default `samples/`): a 20 s programme (bars and tone,
  black and silence, picture and noise, black and silence; timecode from 10:00:00:00) as ProRes 422 HQ/MOV, DNxHR SQ/MXF and H.264+AAC/MP4 (when
  the ffmpeg has libx264), a ramp with pixels outside broadcast range, and a 2.39:1 letterbox. ~45 s, ~480 MB.
- `docs/`: `backlog.md`, `decisions/`, `dependencies.md`, `notes/origin.md`.
- `.github/workflows/ci.yml`: ffmpeg, format, build, samples, test (ubuntu-26.04). `.github/dependabot.yml`: actions and NuGet weekly.
