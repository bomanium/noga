# Job rows that explain themselves

Asked 2026-11-04, after one status style was merged (decisions/2026-11-04-status-style.md): which of the UI review's
backlog items next.

- **Job rows** (recommended): rows in the web UI and the app that say why a check didn't pass, show the folder rather
  than the full path, a short error and the elapsed time, with Report as the main action
- The web UI's gaps first (keyboard, a bad path, feedback on Check, duplicates, "check all")
- Stop here

**Answer: job rows.**

## What was built

- `QcReport.Reason`: the first failure's message (else the first warning's) and how many more failures and warnings
  there are ("Integrated loudness -34.8 LUFS (-11.8 LU from -23 LUFS) (and 2 more)"); null when there are none.
  `Jobs` keeps it on the job (`Job.Reason`).
- `Job.ShortError` (the error with the file's path replaced by its name, since the row names it), `Job.Folder`,
  `Job.Elapsed(now)` (measuring so far, or how long it took) and `Job.Format` ("12 s", "3 min 05 s"); the web UI's
  jobs JSON carries `reason`, `shortError` and `folder`.
- Both the web UI and the app show each row as: the badge; the file's name; its folder and "took 12 s" (or the time
  so far, each second, while measuring), the full path on hover; the reason or the short error. Report is the accent
  button, JSON a quiet link or a small button.
- The README's screenshots of the web UI and the app are redone.
