# Platform spec profiles

Question 1: what next after the shared-machine mode.

Choices:

1. Platform spec templates (recommended): profiles beyond EBU R128, chosen with --profile.
2. HTTPS for a shared server.
3. A native app shell.
4. Stop here for now.

Answer: 1.

Question 2: which profiles to ship beside ebu-r128 (more than one could be chosen). The figures come from vendor
summaries (NUGEN, RTW, iZotope's documentation); only ATSC's were checked in its own document (A/85). Specs that
measure dialogue-gated loudness (Netflix and the like) are left out: mediaqc measures programme loudness.

Choices:

1. atsc-a85 (US): -24 LKFS within ±2 LU, true peak at most -2 dBTP.
2. op-59 (Australia, Free TV): -24 LKFS within ±1 LU, at most -2 dBTP.
3. arib-tr-b32 (Japan): -24 LKFS, at most -1 dBTP; no tolerance found, ±1 LU assumed.
4. Profile files: --profile FILE.json, a delivery's own thresholds.

Answer: all four.

Question 3: how the profile is chosen.

Choices:

1. `--profile NAME|FILE` on `check` and on `serve` (whose checks all use it; the page shows which); ebu-r128 stays the
   default (recommended).
2. As 1, and a profile menu beside each Check button in the page.

Answer: 1.

With the code: `Profiles` (AtscA85, Op59, AribTrB32: ebu-r128's settings with their loudness target, tolerance and
true peak; their tolerance passes, outside it fails, no warning band), `Profiles.Get(nameOrFile)` and
`Profiles.Read(json)`: a file names the profile and may start from a shipped one (`basedOn`, default ebu-r128),
changing any threshold or setting (camelCase as `Profile`'s; unknown fields refused, comments and trailing commas
allowed, values checked for range). An unknown profile is a usage error naming the known ones. The ARIB tolerance and
the OP-59 and ARIB figures are as the secondary sources give them, to be checked against the originals before a
customer relies on them.
