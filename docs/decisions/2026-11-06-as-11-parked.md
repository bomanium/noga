# AS-11 UK metadata parked

Asked 2026-11-06. With the backlog's Next list empty again after the repeated frames, the owner moved "AS-11 UK
metadata in MXF (ffprobe's tags)" up from Maybe. The question that offered it said it was checkable against ffprobe's
tags.

Found when starting: that was wrong. FFmpeg's MXF demuxer (libavformat/mxfdec.c) doesn't parse descriptive metadata
at all, so ffprobe gives none of AS-11's fields (programme title, episode, shim name and version, durations and the
like). On an MXF, ffprobe's format tags are the identification set's (company, product, version), the operational
pattern, the UIDs, the material package's UMID and the timecode. FFmpeg can't write AS-11 either, so test files would
need BBC's bmx (BSD-3; not in Ubuntu's packages, built from source).

Question: how to go on.

Choices:

1. Park it (recommended): back to Maybe with this finding, and take another item. AS-11 is mainly a UK DPP delivery
   requirement, and the README already says Noga is not a DPP compliance replacement.
2. Build it with MediaInfo as the reference: Noga reads the AS-11 Core and UK DPP sets from the MXF itself; the tests
   make AS-11 files with bmx (built in CI, used only in tests) and check each field against MediaInfo's (BSD-2, in
   Ubuntu's packages). An exception to the check-against-FFmpeg rule, like the shot list.
3. Won't do: to backlog-done.md, as FFmpeg can't check it.

Answer: 1. The backlog item stays in Maybe, its Why naming the finding and how it would be built.
