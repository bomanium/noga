# The set check: what a book's files must have in common

Asked 2026-11-15, when the backlog's item (a book as one check: `noga check FOLDER`,
[2026-11-09-set-check.md](2026-11-09-set-check.md)) was taken up. That decision left open what the summary compares
and the tolerance.

## What does the set judge across the files?

ACX rejects a book whose files differ in format (every file mono or every file stereo, the same codec and rate), and
asks for levels that match, without a figure.

- **Format fails, levels warn** (recommended): a failure when the files differ in codec, container, sample rate,
  channel count or bit rate; a warning when a file's RMS level is further than the tolerance from the others.
- Both fail: stricter than anything ACX publishes for levels.
- Format only: each file's RMS and peak listed side by side, as information.

**Answer: format fails, levels warn.**

## The tolerance for levels

ACX's -23 to -18 dB RMS window is 5 dB wide; nothing says how close a book's files must be.

- **2 dB from the median** (recommended): a file whose RMS is more than 2 dB from the set's median is flagged. The
  median isn't moved by one odd chapter, and 2 dB is a step a listener notices between chapters. Settable in a profile
  file.
- A 3 dB spread between the loudest and the quietest file, naming both: one odd file makes the whole set the finding.
- 1 dB from the median: what careful mastering aims for, but it would flag many books ACX accepts.

**Answer: 2 dB from the median.**

## Under which profiles?

- **Only where the profile asks** (recommended): any profile checks a folder's files and gives one summary and one
  exit code; the format and level comparisons are judged only where the profile has a `set`, which acx and acx-master
  get and a profile file can add. A folder of unrelated video deliveries isn't failed for differing.
- Every profile: mixed formats fail under ebu-r128 too.
- acx only, no profile setting.

**Answer: only where the profile asks.**

## How it is built

- `noga check FOLDER` checks the folder's own media files (`MediaFiles.Directly`: not its subfolders', a book being
  one folder; hidden files and reports left out; by name), each as `noga check FILE` would, its reports beside it or
  in `--out`'s folder. Then the set's report, `FOLDERNAME.set.qc.html` and `FOLDERNAME.set.qc.json`, with them:
  every file's verdict, the reason it didn't simply pass, its RMS level and sample peak, linked to its own report;
  and what was found across the files (`Noga.Checking`'s `SetChecker`, Core's `SetReport`, `SetHtml`, `SetJson`).
- `Profile.Set` (`SetSpec`; a profile file's `"set": { "sameFormat": true, "levelTolerance": 2 }`, those the values
  when left out, `"levelTolerance": null` to report the levels without judging them); `Profiles.Acx` and `AcxMaster`
  have one.
- `set.format`: each of these has one value throughout, the most common one being the set's (the earliest file's
  among equals), and a file with another fails, named with each difference: the container; the first audio track's
  codec, sample rate, channel count and bit depth, and its bit rate to the kb/s for an MP3 and for PCM (other codecs'
  bit rates are averages that differ from file to file); the number of audio tracks; a picture's codec, frame size
  and frame rate. All ffprobe's values, as each file's own report has them.
- `set.level`: each file's `level.rms` (astats' Overall RMS level, which a profile with a set reports even without an
  RMS window, as information) against the median of the set's (an even count's: the middle two's mean); further than
  `LevelTolerance` at the report's 0.1 dB is a warning that names the file. Arithmetic on figures already checked
  against astats; a test checks each file's level and the median against astats on a generated book.
- One exit code: 2 when a file couldn't be read (the set wasn't checked whole; the other files are still checked and
  reported), else 1 with a failure in any file or in the set, 3 with warnings only (1 with `--warnings-fail`), 0 when
  everything passed.
- Not built here: the web UI and the app still show a folder's files as checks of their own.
