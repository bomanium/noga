# The local web UI

The owner chose, after the release workflow, to tag v0.1.0-alpha.1 and then build the local web UI that
2026-10-31-product-shape.md kept for later (`mediaqc serve`, on the same core as the CLI). Asked about a web UI against
a desktop app, the answer was: the web UI first (it reuses the HTML report and the release as they are; a thin native
shell around the same page can come later).

Question 1: how files get into it. A browser can't give a page a file's path, and uploading a 100 GB master to
localhost is slow and doubles the disk it takes.

Choices:

1. Picked on the server (recommended): the page browses the folders of the machine mediaqc runs on (or takes a
   pasted path), and mediaqc reads the file where it is; the reports go beside it, as the CLI writes them.
2. A watch folder (`mediaqc serve --watch FOLDER`), with picking too.
3. Uploaded by the browser.

Answer: 1.

Question 2: what it is built with.

Choices:

1. ASP.NET Core minimal APIs (MIT, part of .NET) and one hand-written page, no front-end framework or build step,
   progress by server-sent events, the HTML report shown as is (recommended).
2. Blazor Server.

Answer: 1.

Question 3: who can reach it.

Choices:

1. This machine only: 127.0.0.1, no login to build (recommended); a shared-machine mode can come later.
2. Localhost by default, `--listen` for a shared machine with a token in the URL.

Answer: 1.

With the code: `mediaqc serve [--port PORT] [--no-open]` (default 8722, opens the browser). Checks run one at a time in
the order asked (each already keeps the cores busy), the same check as `mediaqc check` (Checker). Beyond listening on
127.0.0.1 only, it refuses a Host other than localhost or 127.0.0.1 (DNS rebinding), and any change without the page's
X-MediaQc header or from another Origin (a cross-site form or fetch); it lists folder and file names and sizes, reads
only the files picked, and serves only the reports it wrote. A release carries ASP.NET Core's runtime (about 20 MB
more) and its licence and notices in licences/aspnetcore/.
